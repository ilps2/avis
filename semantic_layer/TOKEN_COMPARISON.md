# 同一视频两种做法：token 消耗对比实验

实验日期：2026-08-06
测试视频：样本7 直播切片 clip_03（89 秒，720×1572 竖屏，H.264）
转写：faster-whisper tiny，47 段，463 字
Tokenizer：Qwen2-VL-2B 真实 tokenizer（mlx-community 缓存模型）

## 方法 A：传统全量多模态（1fps 抽帧 + 全文转写）

输入 = 89 帧画面 + 47 段语音转写文本。

| 计费口径 | 计算 | token |
|---|---:|---:|
| Qwen2-VL 真实 tokenization | 89 帧 × 5,824 + 337 转写 | **518,673** |
| GPT-4o 风格估算（AVIS 公式：720p ≈ 300/帧） | 89 × 300 + 337 + 500 开销 | **27,537** |

注：Qwen2-VL 对竖屏视频按块切分，一帧 720×1572 产生 5,824 个图像
token；AVIS 文档的 ~300/帧是 GPT 系平铺计费的下界。两者都是真实
存在的计费口径，模型不同差距巨大。

方法 A 本地未实跑：51.8 万 token 的输入在 2B 模型上也需要数 GB 的
KV 缓存和数十分钟生成，本地不可行；若走云端 API，按上述 token 计费。

## 方法 B：语义层文本（AVIS 思路，零图片）

输入 = 场景描述 8 条 + 对象出现记录 59 条 + 语音转写 47 段，
全部带时间戳，纯文本。

| 项目 | token |
|---|---:|
| 场景描述 | 184 |
| 对象记录 | 1,241 |
| 语音转写 | 1,019 |
| **合计（真实 tokenizer）** | **2,456** |
| 加上 chat 模板后实际发送 | 2,534 |

### 真实理解输出（Qwen2-VL-2B 本地实跑，7.0 秒）

输入 2,534 token → 输出 400 token：

> 这段视频在讲一款口红产品。主播在镜头前拿着口红，向观众介绍这款
> 口红，并且向观众推荐了其他相关产品。
> 关键时间点包括：11.52s、19.2s、21.12s、24.0s …… 主播送了一只
> 口红，向观众推荐了这款口红。

（2B 模型输出有重复，但产品、动作、时间点全部抓对了。换更强模型
或换 API 不改变 token 数量，只改变质量。）

## 方法 B-hit：查询后只理解命中片段

对查询"口红"，语义层先定位到命中窗口，再只把命中片段交给模型：
输入 = 命中场景 1 条 + 命中对象若干 + 命中语音 2 段。

| 项目 | token |
|---|---:|
| 实际发送 | **260** |
| 输出 | 51（0.9 秒） |

真实输出：

> 口红在这段视频中出现在第 76.29-89.0s 的时间点。主播对口红的介绍
> 要点是：a woman in a black dress is holding a box，以及主播提到的
> "口红"。

## 汇总对比

| 做法 | 输入 token | 相对 A(GPT口径) | 相对 A(Qwen口径) | 本地实跑 |
|---|---:|---:|---:|---|
| A 全量（Qwen 口径） | 518,673 | 18.8× | 1× | 不可行 |
| A 全量（GPT 口径） | 27,537 | 1× | 0.053× | 不可行 |
| B 语义层全文 | 2,456 | **11× 省** | **211× 省** | ✅ 7.0s |
| B-hit 只理解命中 | 260 | **106× 省** | **1,995× 省** | ✅ 0.9s |

## 结论

1. **省多少取决于模型计费口径**：对 GPT 系平铺计费约省 11 倍，
   对 Qwen2-VL 这类按分辨率切块的模型约省 200 倍。
2. **语义层省的是"看"的钱**：B 与 A 输出同一段视频的理解结论，
   但 B 全程没看一帧画面——信息由对象向量 + 场景描述 + 转写承载。
3. **B-hit 是最终形态**：先索引定位（免费），再只让模型看命中片段。
   查询次数越多，节省越放大。
4. **token 数是比价格更稳的指标**：模型降价后，200 倍差距仍然成立。

# 精度审计：省 token 的同时牺牲了多少理解精度？

诚实结论：**会牺牲。语义层是"有损压缩"，损失来自五个环节**，但每
一环都有对应的"精度调节旋钮"，不是省 token 就必然瞎。

## 实测 1：ASR 层（损失最直观）

同一段 89 秒音频，三个 Whisper 模型真实转写对比：

| 模型 | 耗时 | 转写质量（真实文本） |
|---|---:|---|
| tiny | 6.4s | "我认识甘喜的混干混油的引擎面积斗机…现在下达美好领旧会给大家送了一只口红" |
| base | 8.4s | "无论您是干脾的混干的混油…现在下达509会给大家送到一只口红" |
| large-v3 | 117.3s | "无论是干皮的 混干的 混油的 以及抿肌 痘肌 那么深蓝的粉气垫…现在下单我们的一号铃就会给大家送到一支口红" |

损失量化：tiny 把"干皮/混干/混油/痘肌/粉气垫/高遮瑕/持妆/下单/一号链接"
几乎全部转错；large-v3 基本正确。

**关键点：换大 ASR 不增加下游 token 数**（token 只跟字数有关），
只增加索引构建时间（6.4s → 117s）。这是第一个精度旋钮。

## 实测 2：检索层（不同查询通道各有盲区）

对象层"真值"：口红实际出现 11 个窗口。对比两种查询：

| 查询方式 | 命中的口红窗口 | 盲区 |
|---|---|---|
| 文字"口红" | 语音层 68.6-69.2s、对象层 84-89s | **漏掉 24-26s、30s、34-35s 等纯视觉出现**（ASR 没提到）；还有大窗口假阳性（face 0-88s 得 0.656 分） |
| 参考图 | 24-26s、30s、34-35s、70-80s（相似度 0.93+） | 漏掉 ASR 里的 68.6-69.2s 语音线索 |

损失量化：文字查询对"只有画面、没人说"的内容召回为 0；参考图查询
对"只说了、没看清"的内容召回为 0。**融合查询 + 重排是第二个旋钮**。

## 实测 3：理解层（输入噪声会传导到输出）

方法 B 的真实总结抓住了"口红产品 + 主播介绍"（方向正确），但输出里
重复出现"11.52s、19.2s、21.12s、24.0s 送口红"——这些时间点部分是
tiny ASR 噪声 + 2B 模型重复生成的**幻觉**。输入层的错误会原样传导
到理解输出。

## 精度损失的五个环节与旋钮

| 环节 | 损失来源 | 旋钮（成本） |
|---|---|---|
| 抽帧率 | 1fps 会漏掉 1 秒内的快变事件 | 提高采样率（索引成本线性增） |
| 检测/跟踪 | 漏检 = 索引里没有 = 永远查不到；IoU 跟踪会断轨 | 多提示词冗余、ByteTrack+Re-ID、增量补检 |
| ASR | tiny 噪声最大 | 换 base/large（**token 不变**，构建时间变长） |
| 描述模型 | BLIP 描述粗，竖屏细节弱 | 换更强 VLM（构建时间变长，token 不变） |
| 检索通道 | 文字 vs 参考图各有盲区 | 多通道融合 + top-k 重排（查询成本几乎不变） |

## 修正后的结论

1. **省 token 和丢精度不是同一个开关**：token 由"你给模型看多少"
   决定；精度由"索引层每个组件多准"决定。把 ASR 从 tiny 换成
   large-v3，token 还是 2,456，但理解输出的可信度大幅提升。
2. **最危险的损失是检测漏检**：它无法用查询补救（索引里没有）。
   缓解靠冗余检测 + 场景层文本兜底 + 增量补检，而不是靠更强的理解
   模型。
3. **真正的产品形态是"精度滑杆"**：
   - 全量 AI：100% 精度，100% token
   - 语义层（tiny + 单通道查询）：~60-80% 精度，0.5% token
   - 语义层（large ASR + 融合查询 + 重排）：~90%+ 精度，1% token
4. 滑杆上的准确数字需要正式评估集（10+ 查询 × 人工标注真值，
   算 precision/recall），这是下一步最有价值的工作。

## 复现

```bash
# 语义层文本 payload 的 token 数（Qwen2-VL tokenizer）
python3 - <<'PY'
from transformers import AutoProcessor
from pathlib import Path
import json
proc = AutoProcessor.from_pretrained(
    Path.home()/'.cache/huggingface/hub/models--mlx-community--Qwen2-VL-2B-Instruct-4bit/snapshots'/'<rev>',
    local_files_only=True)
tok = proc.tokenizer
base = Path('demo_clip03_v2')
text = ''
for name in ['scenes.jsonl','objects.jsonl','asr.jsonl']:
    for line in (base/name).read_text(encoding='utf-8').splitlines():
        r = json.loads(line)
        text += f"[{r.get('t0', r.get('start'))}-{r.get('t1', r.get('end'))}s] {r.get('caption') or r.get('description') or r.get('text')}\n"
print(len(tok.encode(text)))
PY
```
