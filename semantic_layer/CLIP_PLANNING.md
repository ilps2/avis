# AI 剪辑规划：plan_clips + 效果测试方法

语义层除了"理解视频内容"，还能直接产出**剪辑清单**：给定一条规则
（查询词 + 对象标签 + 可选关键词），返回带证据的时间片段列表。

## plan_clips 做什么

```
规则(查询词/对象标签/关键词)
  -> 逐条目候选（对象出现片段 + 场景 + ASR 句子）
  -> 对象标签过滤 + 窗口去重 + 邻近合并
  -> 语音过滤（可选：只保留有语音的片段）
  -> 场景边界吸附（1.5s 内对齐剪辑点）
  -> 超长片段按场景边界切分（目标时长）
  -> 关键词交叉验证（可选：最终片段语音必须含关键词）
  -> 剪辑清单（t0/t1/时长/命中证据/语音文本）
```

CLI：`python3 semantic_layer.py plan <idx> --text "口红" --objects lipstick
--keywords 口红 --min-dur 3 --max-clips 5`

MCP：`plan_clips(idx_dir, text, object_labels, keywords, min_dur, ...)`

## 实测效果（89 秒直播切片，4 条剪辑规则）

用关键词交叉验证（"讲解类"规则）：

| 规则 | 片段数 | P@k | GT召回 | 边界误差 | 均长 |
|---|---:|---:|---:|---:|---:|
| 口红+讲解 | 1 | 1.00 | 0.33 | 1.4s | 12.7s |
| 价格+优惠 | 3 | 1.00 | 0.53 | 0.9s | 15.8s |
| 二号链接 | 3 | 0.67 | 1.00 | 3.8s | 12.7s |
| 粉底气垫 | 1 | **1.00** | **1.00** | 3.9s | 12.7s |
| **平均** | | **0.92** | **0.72** | **2.5s** | |

不加关键词（纯视觉/语义检索）时，召回更高但精度下降（前几版实测
平均 P 0.62-0.69）——这是"找得全"和"剪得准"之间的本质取舍。

## 怎么测试这个方法的效果：三层层级

### 第 1 层：自动化代理评估（已实现，eval_clips.py）

```bash
python3 eval_clips.py   # 输出 P@k / GT召回 / 边界误差 / 均长 / 语音覆盖
```

真值 = 代理真值（对象层窗口 + large-v3 ASR 关键词窗口）。指标：

- **P@k**：规划片段里与真值重叠 ≥1s 的比例（剪出来的有没有用）
- **GT召回**：真值窗口被至少一条规划片段覆盖的比例（该剪的剪到没）
- **边界误差**：规划片段的起止点离最近真值边界的平均秒数（剪辑点准不准）
- **均长 / 语音覆盖**：编辑可用性（太碎不行，没语音的"讲解"不行）

局限：真值与规划器同源（对象层 + large-v3），是**自证测试**，
适合回归和调参，不适合宣传精度。

### 第 2 层：人工真值标注（下一步，最值得做）

1. 选 3-5 个视频，每个视频定 5-10 条剪辑规则
2. 人工逐帧标注"值得剪的窗口"（秒级）和"不要剪的窗口"
3. 跑 plan_clips（多组参数：keywords 有/无、min_dur 3/5/10、
   target_dur 10/20/30）生成参数曲线
4. 算窗口级 P/R + 边界误差，用第 1 层脚本直接换真值即可

### 第 3 层：编辑者体验评估（最终标准）

让真人剪辑师/用户对每条规划片段打三个分（1-5）：

- **语义完整**：这刀切出来，观众能不能看懂在讲什么
- **画面完整**：起止点是否在镜头切换处、有没有半句话/半动作
- **可用率**：100 条规划里能直接用的比例（工业指标）

这三项是语义层永远无法自己打的分，因为"剪得好"最终是人的主观
判断——这正是需要人工评估的原因。

## 已知取舍（也是调参指南）

1. **关键词过滤提升精度、牺牲召回**：P 0.69→0.92，R 0.87→0.72。
   "纯视觉收集"规则不要传 keywords，"讲解/口播"规则要传。
2. **场景对齐提升剪辑点质量、扩大窗口**：边界误差从 8-36s 降到
   ~2.5s，但短命中可能被吸附进整场。1.5s 吸附阈值可调。
3. **宽窗口过滤（max_window=30）**：排除全程跟踪的主角轨迹，
   避免把全片合成一条。
4. **目标时长（target_dur=20）**：超长连续段按场景边界切成可用的
   短视频片段。
